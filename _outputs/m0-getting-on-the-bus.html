Module 0 · Study the Play

Getting on The Bus gives you the writing, diagram, environment, and help-seeking habits that every later Java module uses.

What this module covers

Getting on the bus means following the course process: predict before you run, complete the handshake, execute, report evidence, and explain the result. The phrase comes from American team sports. Its literal meaning is to follow the process every time.

  • Simplified Technical English: active voice, one topic per sentence, and consistent terms.
  • Markdown task cards with headings, code blocks, lists, checklists, and tables.
  • Mermaid flowcharts that show a process and a decision.
  • A Java development environment, the compile-run cycle, and compile-time errors.
  • GitHub Codespaces, local VS Code, the course verifier, and honest AI-teammate use.

Execute-gate handshake

State all four parts to your coach. The gate opens when your coach says “Agreed.”

PartYou say
Goal“The program must…”
Constraints“I may change… I may not change…”
Prediction“I expect the output to be…”
Success check“We know it works when…”

Learning goals

  1. Apply the three STE rules to a task description.
  2. Format a task card in Markdown and diagram a process in Mermaid.
  3. Set up or access Java, then write and run a Hello World program.
  4. Read a compile-time error and identify the problem.
  5. State the four handshake parts and interpret verifier output.
  6. State the five AI-teammate rules and disclose AI use in one sentence.

The compile-run cycle

Write Java source, compile it with javac, then run the resulting bytecode with java. Fix the first compiler error before you run the program.

Source file (.java)  →  javac  →  Bytecode (.class)  →  java  →  Output

Work surfaces and verification

GitHub Codespaces and local VS Code support every graded task. Codespaces have no graphical display, so Module 8 accepts a console event path and does not reduce credit for it.

$ bash scripts/verify.sh all

AI teammate policy

The AI may be the player. You remain the coach. Predict before you run, disclose what the AI produced, and explain every line you submit. Only a person opens the execute gate.

Before you continue

  • I can write a task card with clear Markdown.
  • I can state goal, constraints, prediction, and success check.
  • I can compile and run HelloWorld.java.
  • I can run the verifier and explain a PASS or FAIL result.
