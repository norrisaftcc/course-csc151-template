# Module 00: Technical Writing, Markdown, and Mermaid

**Course:** CSC 151 Java Programming I
**Position in sequence:** First module (before all coding modules)
**Estimated time:** 1–2 class sessions

---

## What this module covers

- Simplified Technical English (STE-100): active voice, one topic per sentence, consistent terms.
- Markdown: headers, bold, code blocks, lists, checklists, and tables.
- Mermaid: how to read and write a flowchart that diagrams a play.

---

## Why this module comes first

Every module in this course uses Markdown files, Mermaid diagrams, and precise written language. Students who understand these tools can read task cards, predict outcomes, and document their work without friction. Students who do not can spend a full session confused by the format rather than the content.

This module also introduces the **handoff** — the structured four-part agreement (goal, constraints, prediction, success check) that opens the execute gate before every coding task. Introducing the handoff in a non-coding context lets students practice the form without the additional load of writing Java.

> **Terminology note:** Other documents in this course use the term *handshake* for the execute-gate agreement. This module uses the preferred term **handoff**: the coach hands the task to the player; the player hands back evidence. The terms are synonymous. Use *handoff* when introducing the concept to new students.

---

## Learning goal

After this module, students can:

1. Apply three STE-100 rules to improve a written task description.
2. Format a task card using Markdown.
3. Read and write a Mermaid flowchart that diagrams a multi-step process with at least one decision.

## Instructor facilitation notes

### Before class

1. Open `lesson.md` on GitHub and confirm the Mermaid diagrams render. If they do not, check that the repository is on a branch that supports GitHub Mermaid rendering.
2. Prepare one example of a poorly written task description to use for the STE warm-up. The worked example in the lesson can serve this purpose.
3. Review the handoff format. The first time students see it, walk through each of the four parts aloud before asking them to complete one independently.

### Running the handoff for the first time

Students often treat the handoff as a form to fill in rather than a shared confirmation. Watch for:

- A player who copies the coach's wording verbatim (the restatement is not yet the player's own words).
- A player who gives a vague prediction: "I think it will work." Ask: "What specific output do you predict?"
- A coach who opens the gate before all four parts are confirmed.

Announce explicitly: "The gate opens when I say 'Agreed.' Not before."

### Common STE mistakes

- Passive voice: "the diagram is drawn by the player" → "the player draws the diagram."
- Compound sentences: "write the step and label the decision" → "write the step. Label the decision."
- Synonym drift: using "handshake," "agreement," and "handoff" interchangeably. Choose one.

### Mermaid facilitation

- Show a broken diagram first (the repair exercise in the lesson). Students who see a syntax error and fix it remember the syntax better than students who only see correct examples.
- After students complete their diagrams, ask each pair to swap files and verify that the other pair's diagram renders and matches the plain-text description.

### Accessible facilitation

- Read Mermaid diagrams aloud using the plain-text descriptions. Every diagram in this module has one.
- Allow students to draw their play diagram by hand before translating it into Mermaid syntax.
- Accept predictions in any written form: prose, table, or numbered list.

## How this module connects to the next

Module 01 (Variables and Expressions) uses the same handoff format and the same Markdown-formatted task cards. After this module, students encounter the format as familiar rather than new. The cognitive load in Module 01 can then focus entirely on Java.

> "You don't throw where they're standing; you throw where they're going to be."
> Literal meaning: close this module by pointing toward Module 01. Students who understand the handoff format will enter Module 01 ready to use it on code, not still learning what the format requires.
